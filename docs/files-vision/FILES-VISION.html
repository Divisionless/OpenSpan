EsotericOS Files

What pains the people — on Windows, macOS and Linux — and how we free them of it.

Synthesis by Fable 5, 2026-08-16, from three cited surveys (Windows 27 items · macOS 28 · Linux 27): research-windows.md · research-macos.md · research-linux.md. Every claim below traces to a row there. Where the row is marked UNVERIFIED it is treated as a hint, not a fact.

What the boards say when you read all three at once

Read separately, each platform's complaints look local: Windows has MAX_PATH, macOS has no Cut, GNOME removed type-ahead. Read together, the same seven wounds appear on every board, decades apart, under different names. Nobody's file manager is bad at files. They are bad at memory, honesty and identity — and every alternative people pay for (Directory Opus, Total Commander, TeraCopy, Everything, Path Finder, ForkLift, Dolphin) sells one of those three back to them.

The seven wounds

1 · Amnesia — it forgets how you left things

Win #1 view settings don't stick (registry "Bags" capped at 5,000) #8 Downloads forced group-by-date mac #3 view/window state resets #27 the spatial Finder was abandoned Linux #23 batch-rename dialog lost resizability

The most-voted Windows complaint of the decade is a cache with a hard cap; Finder honours per-folder views only inside Home; Apple threw away spatial memory in 2007 and users have asked for it back ever since.

2 · It lies about operations

Win #10 copy ETA (Raymond Chen, 2004, unchanged) #11 "Calculating…" stall #27 non-transactional undo #12 accidental drag = move mac #2 ⌘Z can permanently delete #5 Replace / Merge / Keep Both roulette Linux #15 partial undo #16 conflict button flips

Progress bars guess, conflicts are asked one dialog at a time, and undo is a hope rather than a record. TeraCopy exists because of this row alone.

3 · It goes blind — and takes the desktop with it

Win #5 "file in use" never names the process #6 unreachable drive freezes the shell 30–45 s #7 SMB crawl mac #13 SMB + .DS_Store litter #15 trash on external volumes Linux #9 KIO/GVfs shares (still discussed by a KDE core dev, 2026) #25 blocking I/O on the main thread #27 disconnect silently shows Home

Synchronous probes on the UI thread, and errors that hide the one fact you need.

4 · Search that doesn't find

Win #2 indexer misses files; Everything is the cure people install mac #22 scope confusion #23 Spotlight exclusions & reindex loops Linux #6 Tracker CPU — advice is "disable it"

Indexers cost too much and still miss; the tool everyone trusts (Everything) reads the MFT directly and never guesses.

5 · The right-click stopped being yours

Win #3 "Show more options" (Microsoft admitted it, Jun 2026) #13 in-process shell extensions freeze the menu mac #1 no Cut, by design, since 1984 Linux #1 type-ahead removed, forks alive 10+ years

Menus truncated for looks, extensions running inside the shell with no timeout, and a verb (Cut) withheld on principle.

6 · Names and paths as booby traps

Win #4 MAX_PATH 260 #9 natural sort with no toggle #21 F2/extension + weak batch rename mac #6 folders-first arrived 2016, still not in Open/Save #20 duplicate naming changed to "file 2 2 2" #17 batch rename limited Linux #17 case-only rename fails

Rules that exist but are hidden, and rules that changed without a word.

7 · Preview and a split personality

Win #15 no Quick Look for 15 years #14 stale thumbnails #17 dark-mode white flash #24 Win95-era Properties dialog mac #19 Quick Look plugins broken by Sequoia #4 Tahoe broke column resizing Linux #4 GTK4 chooser (thumbnails after 18 years) #11 video thumbnails

Two UI generations stitched together, and previews that depend on fragile in-process plugins.

Adjacent, and treated honestly rather than "solved": cloud sync opacity (Win #23 OneDrive; mac #7–#12 iCloud evictions, "waiting to upload", the black box) — we do not own sync, but we will never hide its state; privacy defaults (Win #22 recents on by default).

What each platform got right — and we keep

Windows

  • Deep drag-and-drop with every app, Open With, property sheets — the shell integration alternatives must re-implement
  • Cut/Copy/Paste as first-class verbs since Win95
  • Everything's instant MFT search (third-party, but the bar)
  • TeraCopy's honest, resumable operations (third-party, but the bar)

macOS

  • Quick Look — Space previews anything, arrows cycle
  • Spring-loaded folders
  • Column (Miller) view, path bar, ⌘⇧G Go to Folder
  • Undo of a move as a concept (once it is safe)

Linux

  • Dolphin: split view (F3), embedded terminal in the current folder, F2 batch rename with counters
  • Drag-drop asks Move / Copy / Link
  • Thunar's speed; Nautilus's simplicity for beginners
  • KIO's protocol transparency as an idea (not its speed)

Rules of thumb they all agree on

  • Folders first, always, everywhere — including pickers
  • Never block the window on I/O
  • Own the context menu; never let a plugin freeze it
  • Dark means dark in every dialog

How we free them — the spine of EsotericOS Files

I · A ledger, not a window

Every operation is planned → shown → done → recorded. Before anything moves, Files scans and shows the plan as a readable diff — collisions resolved once, per item or for all (Replace / Skip / Keep both), never one dialog at a time. It then executes with a per-item journal (what went where, from where, when), and the journal is a browsable timeline: "what happened to my files today" is a view, not a memory. Undo is a unit reversal of a journal entry — cross-volume undo restores, it never deletes (mac #2 becomes impossible). An accidental drag-move is one click back. Progress is bytes-honest: throughput and remaining, no ETA theatre; the copy starts immediately while enumeration streams. Partial failures land in the journal with the reason, and can be retried from there.

II · Identity, not paths

Files knows a file by volume + file identity (NTFS file ID / change journal), not by its path string. So per-folder view state, tags, thumbnails, recents and column widths survive rename and move, have no 5,000-folder cap, and cannot be lost to a registry cache. Long paths are simply paths (\\?\ internally, never shown). Spatial memory returns as a choice: a folder can remember its window. Search has two honest engines — instant name search over the MFT/USN journal for local NTFS (Everything's approach, no daemon churn) and opt-in content search per folder — and the scope is always a visible chip ("in D:\_EsotericOS ▾"), never a guess.

III · Honesty surfaces

Every "why did that happen" has a visible answer. "File in use" names the process (Windows has the API — Restart Manager RmGetList — Explorer never calls it) and offers to close it. A disconnected share is a state card, not a freeze and not Home; every mount has its own timeout and cancel. Sync/dataless state is an attribute you can see and sort by. The sort rule is shown (natural / strict, folders first). Rename keeps the extension unselected; batch rename has regex, counters, casing and a live preview diff; case-only rename works on FAT; one duplicate-naming rule ("name (2)") everywhere. Cut exists, is undoable, and cut items dim without hiding their thumbnails (Linux #24). Extensions run out of process with a timeout: nothing a plugin does can freeze the menu. Recents are opt-in.

IV · One body, one skin

One framework end to end (WPF, EsotericOS tokens): no legacy dialog, no white flash, dark means dark. Space is Quick Look, built in, with previewers isolated in a helper process so a bad handler shows "preview unavailable" instead of taking the window. Thumbnails are keyed by identity + change journal, so they are never stale. Column view and split view are equals to list view; tabs are first-class; drag-and-drop shows its effect and asks Move / Copy / Link when it is ambiguous. And it lives where EsotericOS lives — same menu bar, same desk, same tray — so the shell and its files stop being two products.
