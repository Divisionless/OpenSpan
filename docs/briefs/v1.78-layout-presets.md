## Decisions already made

1. A preset stores window identity + the monitor's STABLE KEY + the rect
   relative to that monitor's work area — never a raw virtual-desktop
   rect and never a DISPLAY name. A preset captured on one topology must
   restore sanely on another.
2. Restore is plan-then-apply: `plan_restore(preset, live_windows)`
   returns a list of intended moves plus a list of windows it could not
   match, and is pure/testable. Applying calls an injected mover
   (default: the thin placement helper); tests always inject a fake.
3. Persistence goes through `config_store.ConfigStore` under this
   feature's own settings key. Never write any product config file.
4. The probe NEVER moves a real window.

## Probe

Capture a preset from the live desk, print it (identities, stable keys,
relative rects), then print the restore plan against the same live desk —
which should be a no-op plan. Read-only; say so in the output.

## Tests

House `check()` idiom, fakes throughout. Cover: capture/restore round
trip, relative-rect math across differing monitor sizes, unmatched
windows reported rather than guessed, missing monitor handled, and
persistence round-trip through a temp-rooted ConfigStore.
