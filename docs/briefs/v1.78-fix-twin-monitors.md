# Brief v1.78-fix — Layout presets must survive twin monitors

A defect found in review, on real hardware. Fix `win/layout_presets.py`
and `win/test_layout_presets.py` only.

## The defect

Doug's desk has TWO identical panels: same model, no EDID serial, so
`monitor_identity` gives them ONE shared `stable_key` (this is by design —
read that module's ladder). `_available_monitors()` builds
`dict[stable_key -> MonitorState]`, which silently collapses the twins to
whichever one it saw last.

Measured on the live desk: capture-then-plan produced moves with delta
exactly `(-1920, 0, 0, 0)` — every window on the second panel resolves
against the first, so a restore would yank those windows one monitor to
the left. The module's own docstring promises capture→plan is a no-op; on
this hardware it is not. Existing tests pass only because their fixtures
give every monitor a unique key.

## The fix

`win/display_profiles.py` already solves this correctly — read it first.
It resolves identities through `monitor_identity.assign()`, which
separates same-key panels by position. Do the same here.

1. A captured window records its monitor's `stable_key` **and an instance
   ordinal**: the index of that monitor among all monitors sharing the
   key, ordered deterministically by `(virtual_x, virtual_y)`.
2. `plan_restore` resolves `(key, ordinal)` to a live monitor. If the key
   is present but that ordinal is not (a twin was unplugged), report the
   window as unmatched with a DISTINCT reason — never substitute the
   surviving twin.
3. Persistence stays backward compatible: an absent ordinal in stored
   JSON reads as `0`.
4. Keep the existing `RESTORE_TOLERANCE` / `within_tolerance` behavior —
   it is still needed for relative→absolute rounding, and it is not what
   caused this defect.

## Tests that must exist (they would have caught it)

- Two monitors sharing one stable key at different positions, windows
  captured on each: capture→plan is EMPTY for an unchanged desk.
- The unplugged-twin case reports unmatched rather than moving a window.
- Stored JSON without an ordinal still loads (reads as 0).
- The existing suite keeps passing unchanged.
