# Brief v2.97 — Hotkey host: the layer that makes window control live

New standalone module `win/hotkey_host.py` + `win/test_hotkey_host.py`.
Pure stdlib, Python 3.13. NO Tk, no app changes — this is the engine the
app will switch on in the next slice.

## What this is

Everything ported so far is dark code. This module is the wiring harness
between them: chords in, window actions out. It is what turns
`window_tiling` geometry into "Ctrl+Alt+Left actually tiles the focused
window".

## Read and reuse (do NOT modify any of them)

- `win/keyboard_interception.py` — the router, chord parsing, the
  single-hook service. Register through it; never install a second hook.
- `win/window_tiling.py` — zone geometry, refinement ladder, constraint
  clamping, restore tracking, work-area selection, and its placement
  helper.
- `win/window_tracker.py` — foreground window, identity, DWM bounds.
- `win/monitor_identity.py` — attached monitors / work areas.
- `win/window_rules.py` and `win/layout_presets.py` — MAY not exist yet
  when you start. Import them lazily inside the functions that need them
  and degrade gracefully (`available=False`) if absent. Do not stub them.
- `win/settings_service.py` + `win/config_store.py` — the feature
  registry and persistence. Register this feature's declarations here.
- Default chords: take them from the old program's tiling module
  (`D:\EsotericOS_Antigrav\src\EsotericOS.Features\Windows\Tiling\TilingModule.cs`
  and `docs\feature-plan.json`). Do not invent your own bindings.

## API

- `WindowActions` — the verbs, each pure-ish and individually callable and
  testable with injected collaborators: `tile_focused(zone)`,
  `refine_focused(direction)`, `restore_focused()`, `center_focused()`,
  plus `apply_rules_now()` / `save_preset(name)` / `restore_preset(name)`
  guarded by module availability. Every verb returns a small result
  object saying what it did or why it did nothing — never a bare bool,
  never a silent no-op.
- `HotkeyHost(actions, router=..., service=...)` with `start()`, `stop()`,
  `is_running`, `bindings()` (the live chord→command table) and
  `collisions()` (delegating to `settings_service`).
- **Safety laws, non-negotiable:**
  - Nothing is installed on import or construction. `start()` is the only
    thing that touches a hook, and it must be explicitly called.
  - `start()` refuses and reports if a hook owner already exists (the
    single-hook law) instead of stacking a second hook.
  - Default enablement is **DISABLED**. The registry declaration for this
    feature is `enabled_by_default=False` — the app ships it off because
    the portal and a rival KVM already hold this machine's keyboard.
  - `stop()` fully releases, and start→stop→start must work.
  - No action ever moves a window belonging to this process.

## Probe

`if __name__ == "__main__":` — print the resolved binding table and any
collisions, then run `tile_focused` and `refine_focused` **against a
window the probe creates itself off-screen** (never the real foreground
window — this desk is in use), printing before/after rects, then destroy
it. Start the hook host, report `is_running`, stop it, report again.
Total hook lifetime under two seconds.

## Tests

House `check()` idiom, injected fakes throughout (no real hook, no real
window). Cover: every verb's decision path including "nothing focused"
and "focused window is ours"; refinement through the ladder; restore is
one-shot; graceful degradation when rules/presets modules are absent;
start refuses when an owner exists; start/stop/start; bindings table
matches the reference defaults; default enablement is False; and a
structural check that no hook install happens outside `start()`.
