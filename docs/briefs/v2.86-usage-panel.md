Add a small usage section to the EsotericOS window in `win/openspan.py`,
fed by the readers landed in `win/usage_monitor.py` (read that module's API
first; do not modify it). This is UI + one background worker, nothing else.

## Placement and look (match the house patterns exactly)

- New section at the END of `pane_system` construction (after the
  "Bluetooth radio" section, around line 6913-6927):
  `desk = _section(pane_system, "System desk — AI usage")`.
- Two rows, one per tool, each a `tk.Label` on `bg=BG` with
  `font=("Consolas", 8)` `anchor="w"` `justify="left"`, driven by a
  `tk.StringVar` (`self.usage_codex`, `self.usage_claude`), colors: tool
  name in the text, value styling via `fg=MUTED` (these are quiet readouts,
  not alarms). Initial text: "Codex  reading local data…" /
  "Claude  reading local data…".
- Row content once data arrives:
  - Codex: `Codex   ● {used_percent:.1f}% of weekly window · resets {local
    MMM DD} · plan {plan_type}` — from `codex_snapshot()`. If None:
    `Codex   no local data (has it run on this machine?)`.
  - Claude: `Claude  today {out}M out + {fresh}k fresh · 7d spend {sum}M
    (cache {cache}B)` — from `claude_burn(7)`: "today" = today's UTC bucket
    (main+subagents), spend = totals fresh+out, cache = totals cache.
    Format numbers compactly (k/M/B, one decimal). If empty: `Claude  no
    local data`.
- Wire `_resolve_brand_fonts` is already handled globally — do not touch
  fonts beyond using FONT_UI/Consolas as specified.

## The worker (the part that can freeze the app if done wrong — laws)

- One daemon thread started at the end of App.__init__ (find where other
  workers start; follow the same style): loop { read both meters, marshal,
  sleep 600 }. First read begins immediately.
- `import usage_monitor` INSIDE the worker function (lazy), not at module
  top.
- The readers do file/sqlite IO — they run ONLY in this worker thread.
  NEVER call them on the Tk thread.
- All Tk updates go through `self.ui(...)` (the marshal defined ~line
  7759) — this app has crashed natively (0xC0000409) from off-thread Tk;
  the law is absolute. Set the StringVars inside the marshaled fn.
- Any exception in a read cycle: swallow, set the affected row to
  `… usage read failed`, keep the loop alive.
- The worker must be `daemon=True` and check `self._closing` (see how
  other loops respect it) so shutdown is never blocked.
