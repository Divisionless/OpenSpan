## Module shape

- PURE CORE (no Windows imports at module level): the router (chord
  model, registration, matching, dispatch order) and the single-owner
  policy, fully unit-testable.
- WINDOWS FILL (ctypes inside functions): the WH_KEYBOARD_LL service —
  install/uninstall, the hook proc discipline from the C# (fast path,
  injected passthrough, Win-release masking). The hook proc must never
  raise (see the WNDPROC law comments in win/openspan.py ~line 3956 for
  the house pattern and why: 0xc000041d).
- CRITICAL PRODUCT CONSTRAINT (state it in the module docstring): the
  running product ALREADY captures the keyboard through its portal
  pipeline, and a rival KVM (Input Director) hooks input on this machine.
  This module therefore INSTALLS NOTHING on import and nothing on
  construction — hook installation is an explicit `start()` the app will
  wire in a later slice, and the single-owner policy is the gate.
- `if __name__ == "__main__":` probe — installs the hook PASSIVELY
  (observe-only: always CallNextHookEx, never swallow), pumps messages
  ~3 seconds, prints how many key events it observed and whether any were
  marked injected, uninstalls, exits 0. Zero interference with live typing.
