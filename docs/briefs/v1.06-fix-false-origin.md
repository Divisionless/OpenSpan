## Why this is a rewrite and not a patch

The current port uses `MagSetFullscreenTransform`. The document is
explicit that whole-desktop magnification is the NON-default `desktop`
scope precisely because "it has no per-monitor variant, so every display
magnifies at once." Doug reported exactly that: *"it zooms all pages."*

The real feature is **scoped to one display**: a click-through layered
host window covering the target monitor, containing a `WC_MAGNIFIER`
control, driven by `MagSetWindowTransform`. Port
`D:\EsotericOS_Antigrav\src\EsotericOS.Platform.Windows\Appearance\DisplayMagnifier.cs`.

## FALSE ORIGIN — the defect Doug is seeing right now

He reports: zooming on his LEFT (non-primary, negative-x) display
"shifts everything towards origin." That is the documented failure.

The transform maps **desktop coordinates to desktop coordinates**, so the
viewport corner needs the monitor's own desktop position as a constant
term:

```
v02 = monitor.X - viewX * level        v00 = v11 = level     v22 = 1
```

The document tabulates the two wrong forms that were shipped first:

| Form | Source pixel at the corner | Symptom |
|---|---|---|
| `-viewX * level` | `viewX + monitor.X / level` | reads as a FALSE ORIGIN anchored near the primary — error shrinks as level rises |
| `-(viewX - monitor.X) * level` | lands inside the primary | another screen's content bleeds in |
| `monitor.X - viewX * level` | exactly `viewX` | **correct** |

**The one rule, quoted from the document:** *"Anything about magnifier
geometry verified only on the primary display is not verified."* The
primary's origin is (0,0), so it multiplies away and cannot tell a
correct formula from three wrong ones. Every geometry test you write
must use a monitor at a NEGATIVE origin.

## Everything else the document requires (do not skip these)

- **One Mag call per frame.** Every `Mag*` entry point waits a composed
  frame — measured 16.3 ms of a 16.7 ms frame. Source rectangle pushed
  ONCE when the overlay is placed; every frame after is a single
  `MagSetWindowTransform` carrying scale and viewport together.
- **Never bracket updates in `WM_SETREDRAW`** — it clears `WS_VISIBLE`
  and strobes the raw desktop through. The document includes the probe
  that proves it.
- **`MS_SHOWMAGNIFIEDCURSOR`** on the control, plus
  `MagShowSystemCursor(FALSE)` while the pointer is over the magnified
  display. This is SESSION-WIDE with no owner and no refcount: a process
  that hides the cursor and dies leaves the user with no pointer.
  Restore on every exit path, retry a failed restore rather than
  recording it done, restore when the pointer leaves, and restore once at
  magnifier startup so a hard kill is repaired by the next launch.
- **Host excluded from its own source region** via
  `MagSetWindowFilterList`, or it magnifies itself forever.
- **One dedicated STA thread** owns the windows and pumps them.
- **Panning only at an edge** — the viewport is STATE, not recomputed
  from the pointer. `EdgePush` moves it by exactly the overshoot.
- **Anchor frozen for the gesture** (600 ms), and a gesture never crosses
  displays.
- **Ramp**: `EaseLevel` in log space against ELAPSED TIME,
  `RampTimeConstantMs = 55`. Viewport carried in FLOATING POINT; round
  only when handing the rectangle to Windows.
- Render loop timing per the document (`VREFRESH` for the period, 1 ms
  timer resolution while zooming, ramp frames post the next frame
  directly, the apply path does not render while the loop runs).
