## Decisions already made

1. Rule evaluation is PURE: `match(rule, window_facts) -> bool` and
   `resolve(rules, window_facts) -> action | None` with the C#'s
   precedence. No Windows calls in the evaluation path.
2. Applying an action uses an injected mover; tests inject a fake. The
   watcher (which listens for window appearance) takes the tracker's
   callback rather than installing its own hook, and installs NOTHING on
   import or construction.
3. A rule must never fight the user: port the C# discipline for windows
   that move themselves after appearing (bounded retries, then give up
   quietly). Never loop.
4. Persistence through `config_store.ConfigStore` under this feature's
   settings key.
