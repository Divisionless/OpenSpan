## DECISIONS ALREADY MADE (do not redesign)

1. **No config dependency.** Enablement comes in as an injected callable
   `is_enabled(plugin_id) -> bool | None` (None = "not configured, use the
   manifest default"). Do not import or invent a config store here.
2. **Loading is discovery + validation FIRST, execution second.** The
   catalog (discover manifests, validate, resolve capabilities, decide
   enablement) must be fully usable and testable with NO plugin code ever
   imported. Actually importing plugin code happens only in an explicit
   `activate()` path.
3. **Be honest about isolation.** C# used a collectible AssemblyLoadContext
   and its own docs say that is isolation, not a security boundary. Python
   is weaker still: an imported module runs with full process privileges,
   and unloading is not guaranteed. State that plainly in the module
   docstring — one paragraph, no euphemism — and note out-of-process
   hosting as the real boundary. Do not pretend to sandbox.
4. **Fault isolation is required**: one bad plugin (bad manifest, import
   error, exception in a lifecycle call) must never take down the host or
   prevent other plugins from loading. Every plugin call is wrapped; the
   failure is recorded on that plugin's record with the reason.
5. Capability enforcement: a plugin may only use capabilities its manifest
   declares AND the host grants; the host bridge refuses anything else
   with a clear error, exactly as the C# does. API version compatibility
   is checked before anything else.

## Shape

- PURE CORE: manifest model + validator, naming rules, capability set
  algebra, api-version compatibility, enablement resolution, catalog
  discovery over a directory tree (reads manifest JSON only — never
  imports), and the load-decision result per plugin.
- RUNTIME: `activate(record, host)` using importlib, wrapped for faults;
  a host bridge object that enforces granted capabilities; deactivate
  best-effort. No threads.
- `if __name__ == "__main__":` probe — builds a temp plugin tree inside
  `tempfile.TemporaryDirectory()` with four fixtures (valid, bad manifest,
  wrong api version, raises on activate), runs discovery + activation, and
  prints one line per plugin showing the decision or the contained fault.
  Exits 0 even though fixtures fail — containment is the point.
