# Brief v2.86 slice 1 — usage reader module (Claude + Codex meters)

New module `win/usage_monitor.py` + `win/test_usage_monitor.py`. Pure stdlib,
Python 3.13, no dependencies. This is the DATA half of a usage panel; no UI.

Every schema below is verified against this machine today — do not improvise
field names.

## What it reads (and the only things it may read)

**Codex plan meter** — newest session event stream:
- Files: `%USERPROFILE%\.codex\sessions\<YYYY>\<MM>\<DD>\rollout-*.jsonl`
- One JSON object per line. Lines with `type=="event_msg"` and
  `payload.type=="token_count"` carry:
  - `payload.rate_limits.primary.{used_percent, window_minutes, resets_at}`
    (floats/ints; `resets_at` is unix seconds; `window_minutes` is 10080 —
    the weekly window; `secondary` is null on this plan, tolerate it being
    populated someday)
  - `payload.rate_limits.plan_type` (str)
  - `payload.info.total_token_usage.{input_tokens, cached_input_tokens,
    cache_write_input_tokens, output_tokens, reasoning_output_tokens,
    total_tokens}` (cumulative for the thread)
- A just-started session file may hold only `session_meta` and no
  `token_count` yet.

**Codex burn history** — `%USERPROFILE%\.codex\state_5.sqlite`, table
`threads`: columns `id, tokens_used, model, created_at, updated_at, source,
cli_version` (`created_at`/`updated_at` unix seconds; `tokens_used` is the
thread's lifetime cumulative total). Open READ-ONLY:
`sqlite3.connect("file:...?mode=ro", uri=True)`. WAL sidecars exist; a
point-in-time read is fine.

**Claude burn history** — `%USERPROFILE%\.claude\projects\<proj>\*.jsonl`
plus `<proj>\<session>\subagents\**\*.jsonl`. Lines with
`"type":"assistant"` carry `message.usage.{input_tokens, output_tokens,
cache_creation_input_tokens, cache_read_input_tokens}`, sibling
`message.model`, top-level `timestamp` (ISO8601 UTC), `sessionId`, and
`isSidechain: true` on subagent records. The corpus is ~1.5 GB / 2300+
files — mtime filtering is mandatory, see the performance law.

## API (pure functions, no module-level side effects)

- `codex_snapshot(codex_home=None) -> dict | None` — walk session files
  newest-mtime-first (bound the walk: stop after ~10 files without a
  `token_count`), stream lines, take the LAST `token_count` in the first
  file that has one. Return `{used_percent, window_minutes, resets_at,
  plan_type, thread_total_tokens, as_of}` where `as_of` is the event's
  `timestamp` (fall back to file mtime, ISO8601). None when no data exists.
- `codex_burn(days=7, codex_home=None) -> dict` — from `state_5.sqlite`:
  `{ "YYYY-MM-DD": tokens }` for the last `days` UTC dates bucketed by
  `created_at`, plus `{"total": int}`. A thread spanning days lands on its
  creation date — acceptable, comment it. Missing DB -> `{"total": 0}`.
- `claude_burn(days=7, claude_home=None) -> dict` — walk project jsonl
  files whose **mtime >= cutoff** only; stream lines; for each assistant
  record sum all four usage fields; bucket by UTC date from `timestamp`.
  Return `{"days": {"YYYY-MM-DD": {"main": int, "subagents": int}},
  "total": int}`. `isSidechain` truthy -> subagents bucket. Malformed lines
  skipped silently.
- `if __name__ == "__main__":` probe — print a compact human block: the
  Codex meter line (`weekly N.N% used, resets <local date>, as of <ts>,
  plan <type>`) and per-day burn tables for both tools (last 7 days).

## Laws

- READ-ONLY everywhere. Never open, stat-then-read, or even glob:
  `auth.json`, `cap_sid`, `.credentials.json`, `*.sandbox-secrets*`,
  anything named *token*/*key*/*secret*. Only `rollout-*.jsonl`,
  `state_5.sqlite`, and `projects\**\*.jsonl` as specified.
- Never read, store, or return message CONTENT from any transcript — only
  numeric usage fields, model names, timestamps, flags. If a parsed object
  contains content, it must not leave the parsing function.
- Performance law: the Claude walk touches only mtime-filtered files and
  streams them; nothing may read the whole corpus. No caching in this
  module — callers own caching.
- Paths derive from `%USERPROFILE%` at runtime; no machine-identifying
  literal (username, drive path, serial) in the source.
- Homes are overridable parameters so tests never touch the real dirs.

## Tests — `win/test_usage_monitor.py`, house `check()` idiom (see
`win/test_brand.py`)

Build synthetic fixture homes with `tempfile.TemporaryDirectory()`:
fabricated rollout jsonl (incl. a token_count-less newest file above an
older complete one), a fabricated `state_5.sqlite` built via sqlite3, and a
fabricated projects tree (main + subagent records, an out-of-window old
file that a correct mtime filter skips via `os.utime`). Cover: snapshot
field extraction + fallback walk, burn bucketing/splits, mtime filtering,
absent-home -> clean empties, malformed-line tolerance, and a structural
check that none of the forbidden filenames appear in the module source.
Run all suites: `C:\Python313\python.exe win\test_usage_monitor.py`, plus
`win\test_brand.py`, `win\test_monitor_identity.py`, `win\test_tray_v4.py`
— all must pass. Run the probe against the real homes and capture output.
