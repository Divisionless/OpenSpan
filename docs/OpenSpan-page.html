What it does

The pointer leaves this machine.

OpenSpan turns a Windows PC into a Bluetooth keyboard and mouse — the real thing, at the protocol level. The iPad and the Macs see a paired input device. They don't see a PC, and they don't need to: there is no client, no agent, nothing installed on the far side.

Cross an edge

Shove the mouse off a screen border and input follows. Hold a side button to cross, or jump straight to the nearest screen.

Keep your clipboard

Copy on the PC, paste on the iPad. Two-way, and marked private so it never lands in another app's clipboard history.

Route your audio

PC sound goes out over the same Bluetooth radio to earbuds, while the keyboard link stays up.

Run three at once

Three radios, three independent Bluetooth identities — an iPad and two managed Macs, each with its own bond.

The trick

Windows won't do this. So a Linux VM does.

Windows deliberately blocks applications from publishing the Bluetooth HID service — the OS reserves it for itself. Linux's BlueZ has no such opinion. So OpenSpan runs a headless Debian VM that owns the radio over USB passthrough and advertises as a real BLE keyboard. The Windows side captures your input and streams it in.

your keyboard / mouse │ low-level Win32 hooks Windows ──────── TCP :9955 ───────▶ Debian VM │ BlueZ GATT (BLE HID) ▼ iPad ──────── TCP :9956 ───────▶ second radio ──▶ Mac ──────── TCP :9957 ───────▶ third radio ──▶ Laptop PC audio ──▶ WASAPI loopback ── UDP :4010 ──▶ PipeWire ──▶ A2DP ──▶ earbuds

Everything is local. No cloud relay, no account, no telemetry — the machines are talking to each other over Bluetooth in the same room.

Built tonight

The window used to need two monitors.

It opened at 2,120 pixels tall and had to be spanned across two screens to see all of it. That wasn't a taste problem — it was two expand flags handing every spare pixel to a canvas that physically could not use them.

  • A proper sidebar. Desk, Devices, Bluetooth, System, Console — one at a time, so the window is as tall as what you're looking at instead of everything at once.
  • Right-click any screen. Set its resolution, refresh rate, rotation and physical size right on the map. Windows monitors show theirs read-only — the PC already knows those — with a Refresh now that re-reads them without clobbering anything you set by hand.
  • Buttons that answer you. They darken when pressed, and say "Pairing…" while they're working, with an honest estimate of how long that takes.
  • One alarm, at the cause. Stop the input bridge and every device dims to a muted green or amber — paused, not broken — while the Start button turns amber. You know instantly why nothing is happening.
  • Settings that stay set. How a device feels — pointer speed, acceleration, scroll direction — now follows the device, not the desk layout. Switching arrangements no longer quietly undoes your tuning.

Good neighbour

It shares the keyboard.

Two apps that both hook the keyboard can't see each other, and Windows hands events to whichever launched last — so which one wins is an accident of startup order. OpenSpan now holds a named lease while it owns your input, and any other input tool can stand down for exactly that window and take the keyboard straight back afterwards.

The lease is a mutex rather than a flag on purpose: if the holder dies without releasing it, the next waiter is told, and reclaims it. A flag would have stayed stuck forever, silently.

Honest bits

Two things worth knowing.

  • Run it as administrator. Windows won't deliver low-level input hooks to a lower-privilege app while an elevated window has focus. If you keep an admin terminal open, the mouse just stops crossing — no error, nothing in any log. The app checks at launch and says so.
  • Press Esc three times to bail. Always. It works when everything else is broken — no sockets, no threads, no reliance on any state the app is tracking.

Free, MIT licensed, open source. It is a Tkinter app and a Debian VM doing the one thing Windows refuses to, and it has 1,236 tests standing behind it because the failures in this problem space are silent ones.
